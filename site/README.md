# Project page

https://m2b3.github.io/CanViT/, deployed from this directory when
`.github/workflows/pages.yml` is run by hand (`gh workflow run pages.yml --ref main`).
Static files only: no build step, no framework, no bundler.

```
data/<bundle>/       recorded rollouts and smooth paths, generated by canvit_pytorch.viz
record_bundles.sh    records every bundle in data/
js/canvit/           the <canvit-*> web components, dependency-free ES modules
js/page.js           behavior specific to index.html
live.html            <canvit-live> on its own page (not linked from index.html)
.live-model/         a local export of the live model (ignored by git; see "Live model")
css/site.css         the page's design tokens and layout
slides/example.html  a reveal.js deck built from the same components
assets/paper/        figures of the paper (below)
assets/logos/        link logos (sources below)
```

## From model to page

A bundle is what the model did, as lossless PNGs plus `manifest.json`. Both
formats are specified in [`canvit-pytorch/docs/viz.md`](../canvit-pytorch/docs/viz.md):

- A **web bundle** (`python -m canvit_pytorch.viz rollout`) is one rollout under
  a viewing policy: per glimpse, the crop the model saw, its canvas (PCA to
  RGB), the ADE20K probe's classes and entropy, and the canvas change.
- A **path bundle** (`python -m canvit_pytorch.viz path`) follows a smooth
  path of viewpoints, one glimpse per sample, with the canvas carried and reset.

The components color and animate those layers and never recompute model
outputs. The colors of rollout layers live in `js/canvit/layers.js` (layer
vocabulary), `ade20k.js` (palette) and `colormaps.js`.

`bash site/record_bundles.sh` (with `$ADE20K_ROOT` set) records every bundle
the page shows; add a scene there. Any number of glimpses and any canvas grid
work. A layer name the vocabulary does not know is an error until it is added
to `LAYERS` in `layers.js`.

## Components

Load once per page: `<script type="module" src="js/canvit/index.js"></script>`.
Every bundle element takes `src` (a bundle directory, relative to the page)
and `t` (glimpse index, from 0); `<canvit-path>` and `<canvit-live>` are
described below the table. Inside a `<canvit-rollout>`, an element without its
own `src` uses the rollout's, and every element follows the rollout's `t`.
Attributes drive state, so setting `t` (by script or a slide fragment) updates
the view. Invalid input (missing file, unknown layer, `t` out of range) shows
the error in place of the element and logs it.

| Element | Attributes | Shows |
|---|---|---|
| `canvit-rollout` | `src t autoplay interval layers` | Owns `t` and playback. Empty: the full default layout. With children: drives them. |
| `canvit-scene` | `src t trail="past\|none"` | Photo, current glimpse box (animated), earlier boxes, outside dimmed |
| `canvit-map` | `src t layer domain` | One layer: `crop`, `canvas`, `labels`, `entropy`, `change`, `writeK` |
| `canvit-legend` | `src t layer max domain` | Largest classes, or colormap and range, or what the colors mean |
| `canvit-mosaic` | `src t` | Every glimpse so far, pasted where it was taken at the resolution it was seen |
| `canvit-decision` | `src t` | EG-C2F bundles only: uncertainty after glimpse `t`, candidate tiles, the tile chosen for `t + 1` |
| `canvit-timeline` | inside a rollout | Play/pause and a filmstrip slider (drag, click, arrow keys, Home/End, Space) |
| `canvit-live` | `model scene autoload` | CanViT-B running in the browser: a glimpse wherever the scene is clicked, at any scale; the model's input, the segmentation and its uncertainty decoded from the canvas |

`domain` sets a scalar map's color range: `unit` (0 to 1), `frame` (this
glimpse's min to max) or `bundle` (min to max over all glimpses). The defaults
in `LAYERS` keep one scale across glimpses (`unit` for entropy, `bundle` for
change), so brightness compares across time. `layers` lists the default layout's maps (default
`canvas labels entropy change`).

Events (bubbling, composed): `canvit-change` `{t}` when an element's own `t`
changes (for a rollout: every step), `canvit-load` `{bundle}`, `canvit-error`
`{error}`, `canvit-pointer` `{x, y}` or `null` (hovered scene position as
fractions; a rollout shares it so every view marks the same point). Rollout
methods: `play()`, `pause()`, `seek(t)`.

`<canvit-path src readout autoplay>` shows a path bundle: the scene with the
viewpoint moving along the recorded curve, the model's input, the annotation,
and the maps with the canvas carried and reset; `readout` is `labels`,
`canvas` or `entropy`. Hovering any scene-aligned panel marks the point in all
of them and names the classes there. Setting `src` loads another bundle;
methods `play()` and `pause()`; event `canvit-load` `{manifest}`.

`<canvit-live model scene autoload>` runs the model exported by
`canvit_pytorch.viz.live` (`model`, its directory; `scene`, an image URL,
center-cropped to a square). A click takes a glimpse centered there; the
wheel, a drag (a box centered where it starts) or the slider set its size,
from the whole scene down to pretraining's smallest scale; arrow keys, `+`/`−`
and Enter do the same from the keyboard. The canvas carries over until
"Reset canvas"; EG-C2F can choose the next glimpse or run a whole episode.
Maps: the ADE20K classes and their entropy (fixed scale, 0 to log 150),
decoded from the canvas after every glimpse, beside the model's input. The
download (a few hundred MB) starts from a button stating its size, or at once
with `autoload`; WebGPU when the browser offers an adapter, WebAssembly
otherwise. Methods `look({row, col, scale})`, `policyStep()`, `runPolicy()`,
`reset()`, `load()`; properties `ready` (a promise), `backend`, `history`;
events `canvit-load` `{manifest, backend}`, `canvit-glimpse` `{t, viewpoint,
chosenBy, stepMs, runMs}`, `canvit-error` `{error}`.

Theme with CSS custom properties, inherited into the components:
`--canvit-glimpse` (box color, default the paper figures' blue),
`--canvit-canvas` (the carried-canvas line, the paper figures' red),
`--canvit-sans`, `--canvit-mono`, `--canvit-ink` and `--canvit-muted` (text),
`--canvit-on-ink` (text on an `--canvit-ink` background), `--canvit-radius`,
`--canvit-focus`, `--canvit-placeholder` (panel background before loading),
`--canvit-dim` (opacity of the dimming outside the glimpse),
`--canvit-legend-height`, `--canvit-move` (box animation duration).

## Slides

`slides/example.html` loads reveal.js from jsDelivr and the components from
`../js/canvit/`. A fragment sets `t` on every element its selector matches on
the slide; with no such fragment shown, targets return to their markup `t`:

```html
<canvit-rollout id="memory" src="../data/street-egc2f">
  <canvit-mosaic></canvit-mosaic>
  <canvit-map layer="labels"></canvit-map>
</canvit-rollout>
<span class="fragment" data-canvit-target="#memory" data-canvit-t="4"></span>

<script type="module">
  import Reveal from "https://cdn.jsdelivr.net/npm/reveal.js@6.0.2/dist/reveal.mjs";
  import "../js/canvit/index.js";
  import { bindFragments } from "../js/canvit/reveal.js";
  const deck = new Reveal({ hash: true });
  deck.initialize().then(() => bindFragments(deck));
</script>
```

## Preview locally

`fetch` does not work from `file://`, so serve the directory:

```bash
cd site && python3 -m http.server 8000   # then open http://localhost:8000/
```

Screenshots taken while checking the page go to `site/.screens/` (ignored by
git).

## Live model

`live.html` expects the exported model in `site/.live-model/` (ignored by
git: the graph is hundreds of MB and is never committed). Export it and check
it against PyTorch as `canvit-pytorch/docs/viz.md` ("Live model") describes,
then serve `site/` and open `live.html`. The public page needs the model
directory hosted at a URL that sends CORS headers, set as `model`.

## Paper figures

`assets/paper/*.svg` are figures of the paper, copied unmodified from the
exports of the paper's figure pipeline (`CanViT-paper-exporter`), which also
produce the manuscript's PDFs; the page links each one at full size.
`assets/paper/data_macros.json` is a copy of the paper's generated number
macros (`latex/data_macros.json` in the manuscript repository, written with
`data.tex`). Every result number on the page sits in
`<span data-macro="name">…</span>`, and `python3 site/check_paper_numbers.py`,
which the Pages workflow runs before deploying, fails when one differs from
the paper's value. Replace these files whenever the paper's figures or numbers
change.
